# Plan: v2 iOS OTA (ad-hoc) dev build publishing

> Mirror the dev-APK pipeline for iOS: build a signed ad-hoc IPA on every develop push and
> publish an OTA install page to `v2.squadquest.app/downloads/`, modeled on the
> `pathways-field-companion` setup (itms-services manifest + co-hosted IPA). Gated off until the
> Apple signing prerequisites are configured.

## Scope

**In:**

- `v2-ipa` job in `v2-publish.yml` (macOS runner): `flutter build ipa --flavor dev` (committed iOS
  `dev` flavor → `app.squadquest.dev` / "SquadQuest Dev"; pointed at prod), install Apple cert +
  ad-hoc profile, publish IPA (`-b<N>` + `-latest`), `manifest.plist`, and `index.html` under
  `downloads/`.
- **iOS `dev` flavor**: a `dev` Xcode scheme + `Release-dev`/`Debug-dev`/`Profile-dev` configs in
  `Runner.xcodeproj`, generated by the idempotent `app/ios/tool/add_dev_flavor.rb` (xcodeproj gem)
  and committed.
- `ios/ExportOptions-dev.plist` (ad-hoc, manual; team id substituted from secret).
- `ios/ota/manifest.plist` + `ios/ota/index.html` (OTA install page; `__BUILD_VERSION__` stamped
  by CI) + `ios/ota/README.md` (Apple-side setup checklist).
- Spec: iOS OTA subsection in `behaviors/ci-cd.md`.
- **Gate:** `if: vars.IOS_PUBLISH_ENABLED == 'true'` so the paid macOS runner is skipped until
  signing is set up.

**Out:** App Store / TestFlight; iOS branch previews; automatic UDID registration.

## Implements

`specs/behaviors/ci-cd.md` (iOS OTA section) + `architecture.md` build channels (iOS flavor).
Reuses the `downloads/` path + v2-bucket write the APK job established — no new infra/IAM.

## Approach

Committed iOS `dev` flavor (built once via the `xcodeproj`-gem script, not hand-edited pbxproj —
generates correct object IDs and is idempotent) so CI builds with a clean `--flavor dev`. The IPA
is co-hosted next to the manifest so the OTA `software-package` URL is a direct HTTPS download
(OTA breaks on redirects), which the LB serves.

## Validation

- [ ] **(blocked on user — issue #454)** Apple setup: register `app.squadquest.dev`, create

- [ ] **(post-enable)** develop push builds + signs the IPA; `manifest.plist` + IPA + install page

## Risks / unknowns

- The iOS `dev` flavor lives in `Runner.xcodeproj` (committed). If the project is regenerated or
  configs are added, re-run `app/ios/tool/add_dev_flavor.rb` (idempotent) to restore the `*-dev`
  configs + `dev` scheme. RunnerTests keep `app.squadquest.RunnerTests` (only the Runner target's
  dev configs get the dev bundle id).
- OTA is unforgiving: manifest URL must be direct HTTPS (no 302), install must happen in real
  Safari on-device, device must be in the profile, Developer Mode on. The install page documents
  all four.
- macOS runner minutes are billable — the gate keeps it off until intentionally enabled.
